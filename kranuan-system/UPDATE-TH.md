## ทำทีละ 3 ขั้นตอน

1. แตกไฟล์ ZIP นี้ จะได้โฟลเดอร์ kranuan-system
2. เปิดหน้า root ของ GitHub kranuanonlinecomunity > Add file > Upload files แล้วลากโฟลเดอร์ kranuan-system นี้ลงไป กด Commit changes
3. รอ Render เป็น Live แล้วเปิดเว็บกด Ctrl+Shift+R

เป็นชุดอัปเดตสำหรับ UI ที่ติดตั้งจากรอบก่อน จึงไม่ต้องลบไฟล์เดิม ไม่เปลี่ยน Firebase Rules, schema.sql, package.json หรือ Environment Variables

## ไฟล์หลัก

- public/delivery-status-animation.html: ไฟล์เดียวมี HTML/CSS/SVG/JavaScript ทั้งหมด ไม่มีไลบรารีหรือทรัพยากรภายนอก เปิดแยกได้ทันที
- public/commerce-customer.js: เชื่อมแอนิเมชันกับออเดอร์จริงและเพิ่มฟอร์มเรียกไรเดอร์รับ–ส่งของ
- public/commerce.css: รูปแบบฟอร์มและกรอบแอนิเมชัน
- server.cjs: เก็บพิกัดจุดรับของเพิ่มเติม และบันทึกคะแนน/ความตั้งใจให้ทิปหลังส่งสำเร็จ

## ใช้ไฟล์แอนิเมชันแยก

ดาวน์โหลด delivery-status-animation.html แล้วดับเบิลคลิกเปิดในเบราว์เซอร์ กดปุ่ม 1–5 เพื่อดูแต่ละฉากได้ ปุ่มนี้ไม่เปลี่ยนออเดอร์จริง

ฟังก์ชันที่ร้องขออยู่ในไฟล์นี้:

    setDeliveryStatus(1); // รับออเดอร์
    setDeliveryStatus(2); // หาไรเดอร์
    setDeliveryStatus(3); // ไปรับของ
    setDeliveryStatus(4); // กำลังจัดส่ง
    setDeliveryStatus(5); // ส่งสำเร็จ

ถ้าจะซ่อนปุ่มทดสอบ:

    configureDelivery({showDemo:false});

หรือเปิด URL /delivery-status-animation.html?demo=0

## ในระบบของคุณ เรียกฟังก์ชันตรงไหน

ชุด ZIP เชื่อมให้แล้ว ไม่ต้องพิมพ์โค้ดเอง

commerce-customer.js จะรับข้อมูลออเดอร์จริงผ่าน centralLoad() เหมือนเดิม แล้ว syncDeliveryFrame() ส่งสถานะให้หน้าแอนิเมชัน:

    frame.contentWindow.setDeliveryBackendStatus(order.status);

ฟังก์ชันนี้แปลงสถานะเดิมของระบบเป็นเลข 1–5 ให้อัตโนมัติ:

| สถานะระบบ | ฉาก |
| --- | --- |
| waiting | 1 รับออเดอร์ |
| ready | 2 หาไรเดอร์ |
| assigned | 3 ไปรับของ |
| picked | 4 กำลังจัดส่ง |
| done | 5 ส่งสำเร็จ |
| cancelled | แสดงยกเลิก ไม่แสดงส่งสำเร็จ |

อัปเดตสถานะใน iframe เดิม จึงเปลี่ยนฉากแบบ fade/slide และไม่เริ่มลูปใหม่ทุกครั้งที่โหลดสถานะ 15 วินาที ใช้ได้กับหลายออเดอร์ โดยแต่ละกรอบผูกกับ order ID ของตัวเอง

ฉากเป็นภาพการ์ตูนประกอบสถานะ ไม่ใช่ตำแหน่ง GPS หรือท่าทางจริงของไรเดอร์

## คะแนนและทิป

- เปิดปุ่มเมื่อสถานะ done เท่านั้น
- ในไฟล์ HTML ที่เปิดแยก คะแนนจะเก็บเฉพาะเครื่อง และทิปเป็นความตั้งใจจะมอบให้โดยตรง
- เมื่อติดตั้ง ZIP นี้ คะแนนและจำนวนทิปจะบันทึกเข้าส่วนกลางที่รายงาน customer_feedback โดยผูกกับออเดอร์และไรเดอร์เดิม
- ระบบตรวจว่าเป็นผู้สั่งออเดอร์นี้และส่งสำเร็จแล้ว ผู้ใช้อื่นหรือไรเดอร์แก้คะแนนแทนไม่ได้
- ทิปเป็นการมอบให้ไรเดอร์โดยตรง ยังไม่มีการตัดเงิน โอนอัตโนมัติ หรือ QR รับเงิน จึงไม่แสดงว่าโอนสำเร็จ
- หากมีระบบชำระเงินจริงในอนาคต ใช้ configureDelivery({onRate:...,onTip:...}) เพื่อเชื่อม โดย callback ต้องรอผลยืนยันจากระบบชำระเงินจริงก่อนส่ง {paid:true}

## หน้าเรียกไรเดอร์

ปรับหน้ารับ–ส่งของเดิม (หมวด เรียกไรเดอร์ / เมนู ส่งของ) ให้เป็นฟอร์มทำงานกับฐานข้อมูลจริง ไม่ใช่บริการรถรับส่งผู้โดยสาร:

1. ใส่ชื่อ เบอร์โทร จุดรับ จุดส่ง รายละเอียดของ และพิกัดถ้าต้องการ
2. แนบรูปสิ่งของ/จุดส่งได้ ตรวจค่าส่งที่โหลดจากเซิร์ฟเวอร์ แล้วกดยืนยัน
3. คำขอสร้างเป็นออเดอร์ parcel สถานะ ready ในคิวไรเดอร์ชุดเดียวกับอาหาร ไรเดอร์ออนไลน์รับได้คนเดียว จากนั้นลูกค้าติดตาม assigned > picked > done พร้อมแอนิเมชันได้

กันการกดซ้ำด้วย Idempotency-Key ราคาใช้จากเซิร์ฟเวอร์ ไม่เชื่อยอดที่ส่งจากหน้าเว็บ พิกัดจุดรับและปลายทางแยกกัน ข้อมูลจัดส่งจดจำในเครื่องเดิมได้

ไรเดอร์ต้องเข้าสู่ระบบและเปิดออนไลน์ หน้าเว็บของไรเดอร์ต้องเปิดอยู่จึงรับการอัปเดตสดได้ ยังไม่ใช่ push notification ตอนปิดเว็บ

## การตรวจที่ทำแล้ว

- ตรวจไวยากรณ์ของ JavaScript ใน HTML และไฟล์ระบบผ่าน
- สร้างภาพจาก SVG ทั้ง 5 ฉากด้วยตัวเรนเดอร์ในเครื่อง เพื่อตรวจภาพและองค์ประกอบ
- ตรวจ HTTP request handler ของเซิร์ฟเวอร์ด้วยฐานข้อมูลทดสอบในหน่วยความจำ: คำขอรับ–ส่งของเข้าคิว, เก็บพิกัดสองจุด, ใช้ราคาเซิร์ฟเวอร์, กันคำขอซ้ำ, ไรเดอร์สองคนรับพร้อมกันสำเร็จเพียงคนเดียว, เปลี่ยนสถานะครบ และเก็บคะแนน/ทิปแบบไม่อ้างว่าโอนเงิน ผ่าน
- ไม่ได้เรียกข้อมูล Firebase จริงหรือแก้เว็บออนไลน์ในการทดสอบ
- เครื่องมือเบราว์เซอร์ไม่อนุญาตเปิดไฟล์ local ในรอบนี้ จึงยังไม่ได้ยืนยันการเล่นภาพเคลื่อนไหวและฟอร์มใหม่ผ่านเบราว์เซอร์อัตโนมัติ
