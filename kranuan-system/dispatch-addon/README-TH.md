# แชทตามงาน พร้อมเพย์ และแจ้งเตือนคะแนน/ทิป

โมดูลเสริม ไม่วางทับ server.cjs, schema.sql, api.js, หน้าแรก, หน้าไรเดอร์, หน้าแอดมิน, owner-portal หรือไฟล์ PWA เดิม

## ติดตั้ง 3 ขั้นตอน
1. แตก ZIP อัปโหลดโฟลเดอร์ kranuan-system จากชุดนี้ที่หน้าแรก GitHub แล้ว Commit changes ตรวจว่ามีเพียง dispatch-start.cjs, dispatch-addon/ และ public/dispatch-center/ เพิ่มใหม่ หากชื่อเหล่านี้มีอยู่ก่อนให้หยุดเทียบไฟล์ก่อน ไม่วางทับงานที่กำลังพัฒนา
2. ที่ Render ของ kranuanonline888 เข้า Settings > Build & Deploy > Start Command เปลี่ยนเป็น: node dispatch-start.cjs แล้วบันทึก/Deploy ใช้ Root Directory และตัวแปร Firebase/APP_ORIGIN เดิม ไม่ต้องเปลี่ยน package.json หรือสมัครผู้ให้บริการรับเงินเพิ่ม
3. เมื่อ Render เป็น Live ปิดแอปแล้วเปิดใหม่ หรือเปิด https://kranuanonline888.onrender.com/dispatch-center/ โดยตรง ให้ไรเดอร์บันทึกพร้อมเพย์และผู้ดูแลอนุมัติก่อนทดลองสร้าง QR

ถ้าต้องกลับไปใช้ระบบเดิม เปลี่ยน Start Command กลับเป็นคำสั่งเดิม เช่น node server.cjs โดยไม่ต้องนำไฟล์เก่ามาทับ ไม่ลบข้อมูลของโมดูลเสริม

## ตั้งค่าบัญชีรับเงิน
ไรเดอร์เข้าสู่ระบบบัญชีเดิม เปิด /dispatch-center/?tab=payee กรอกชื่อผู้รับเงินจริงกับเบอร์โทรไทย 10 หลักที่ลงทะเบียนผูกพร้อมเพย์แล้ว ชุดนี้รองรับพร้อมเพย์แบบเบอร์โทร ไม่ใช้เลขบัญชีธนาคารทั่วไปหรือเลขบัตรประชาชน

ผู้ดูแลเข้าสู่ระบบแอดมินเดิมก่อน เปิด /dispatch-center/?tab=admin ตรวจหมายเลขและชื่อเจ้าของบัญชีจริง ติ๊กตรวจแล้วและอนุมัติ การตรวจนี้เป็นการตรวจโดยผู้ดูแล ไม่ใช่ระบบตรวจชื่อบัญชีจากธนาคารอัตโนมัติ เปลี่ยนข้อมูลรับเงินต้องอนุมัติใหม่ QR ที่ยังไม่แจ้งชำระจะถูกพัก หากมีรายการแจ้งชำระรอตรวจ ต้องตรวจรายการนั้นก่อนเปลี่ยนบัญชี

## จ่ายค่าบริการส่งของ/ส่งคน
หลังไรเดอร์รับงาน ลูกค้าเปิดรายละเอียดงาน > QR / การชำระเงิน > สร้าง QR ค่าบริการ ยอดมาจาก fee_satang ของออเดอร์บนเซิร์ฟเวอร์ ไม่รับยอดหรือผู้รับโอนจากลูกค้า รองรับค่าบริการส่งของและส่งคน ไม่เก็บค่าอาหารหรือค่าสินค้าร้านค้าผ่าน QR ใบนี้เพื่อป้องกันเรียกเก็บซ้ำกับระบบร้านเดิม

ลูกค้าสแกนผ่านแอปธนาคาร หรือกดบันทึก QR เป็นรูปเพื่อนำเข้าแอปธนาคาร ตรวจชื่อผู้รับและยอดในแอปธนาคารก่อนโอน เมื่อโอนแล้วจึงกดแจ้งไรเดอร์ตรวจสอบ แนบสลิปได้แต่ไม่บังคับ สลิปไม่ใช่หลักฐานว่าระบบตรวจเงินเข้าแล้ว

ไรเดอร์เปิดรายการ ตรวจธุรกรรมเงินเข้าในแอปธนาคารของตนจริง ติ๊กตรวจยอดและผู้โอนแล้ว กรอกเลขอ้างอิงรายการธนาคาร และกดยืนยันรับเงิน เลขอ้างอิงเดียวกันใช้ยืนยันสองรายการของไรเดอร์เดียวกันไม่ได้ สถานะจะแสดงว่าไรเดอร์ยืนยัน ไม่ใช้คำว่ายืนยันจากธนาคาร ระบบไม่อ่าน SMS หรือดึงบัญชีธนาคาร และไม่ยืนยันชำระอัตโนมัติ

มีสถานะแยกชัดเจน: รอสแกนจ่าย > ลูกค้าแจ้งโอนแล้ว/รอตรวจ > ไรเดอร์ยืนยันรับเงินจริง เมื่อแจ้งโอนหรือยืนยันแล้วจะไม่แสดง QR ซ้ำเพื่อป้องกันจ่ายซ้ำ ไม่เปลี่ยนสถานะจัดส่งอัตโนมัติตามสถานะเงิน

หากยกเลิกงาน QR ที่ยังไม่แจ้งชำระจะถูกพัก หากโอนไปแล้ว ไรเดอร์ยังบันทึกการรับเงินจริงได้ การคืนเงินและข้อพิพาทต้องติดต่อผู้ดูแลจัดการนอกระบบ ชุดนี้ไม่มีการคืนเงินอัตโนมัติ QR ส่วนบุคคลที่เคยบันทึกเป็นรูปไม่สามารถยกเลิกที่ธนาคารได้ จึงให้ใช้ QR จากออเดอร์ปัจจุบันเสมอ

## ทิปและคะแนน
หลังส่งสำเร็จ ลูกค้าสร้าง QR ทิป 1–10,000 บาทได้ เลือกจำนวนไม่เกินสองตำแหน่งทศนิยม จ่ายตรงให้ไรเดอร์และใช้ขั้นตอนยืนยันเงินจริงเดียวกัน ป้องกันการสร้างทิปค้างหลายยอดในงานเดียวกัน

คะแนนจากปุ่มเดิม /orders/:id/feedback จะถูกนำมาแจ้งเตือนไรเดอร์โดยอัตโนมัติ พร้อมตรวจว่าผู้ให้คะแนนคือผู้สั่งจริง ไม่เชื่อข้อมูล rider_id หรือคะแนนที่บัญชีอื่นส่งปลอมเข้ามา

การกดทิปใน UI เดิมซึ่งเป็นแค่ tip intent จะแจ้งว่า ลูกค้าแจ้งว่าจะให้ทิป และยังไม่ถือว่าเงินเข้า เมื่อจ่ายผ่าน QR ใหม่และไรเดอร์ยืนยันแล้ว จะมีแจ้งเตือนทิปที่รับจริงแยกต่างหาก

## แชท
ใช้เฉพาะลูกค้าผู้สั่งกับไรเดอร์ที่ได้รับมอบหมาย เมื่อสถานะ assigned/picked และหลังสถานะ done อีก 1 ชั่วโมง ใช้เวลาจบงานจาก order_events เป็นหลัก ไม่ต่ออายุแชทเพราะมีการแก้ข้อมูลอื่น ส่งได้เฉพาะข้อความไม่เกิน 1,500 ตัวอักษร ชุดนี้ไม่รับไฟล์แนบในแชท

ครบเวลาแล้วปิดทั้งการอ่านและส่งข้อความ และล้างข้อความแชทที่ปิดแล้วในรอบตรวจข้อมูล งานที่ยกเลิกจะปิดแชททันที ผู้ดูแลและไรเดอร์อื่นไม่สามารถเข้าดูแชทของงานที่ไม่ได้เป็นคู่สนทนา

## การแจ้งเตือน
กระดิ่งในหน้าเดิมและหน้า /dispatch-center/ แสดงข้อความใหม่ คะแนน ทิป และการแจ้งชำระเงิน ใช้ SSE พร้อมตรวจซ้ำเป็นช่วง ๆ เปิดเสียงได้ด้วยปุ่มลำโพง และขออนุญาตแจ้งเตือนเบราว์เซอร์จากหน้าแจ้งเตือน รองรับขณะเปิดหน้าและเชื่อมต่ออยู่ ยังไม่ใช่ Push เมื่อปิดแอปสนิท บางเบราว์เซอร์/LINE LIFF ไม่รองรับแจ้งเตือนระบบ ให้ใช้กระดิ่งและเสียงในแอป

## ข้อมูลและการรักษาเวอร์ชัน
bootstrap โหลด server.cjs ปัจจุบันผ่าน exports เดิม เพิ่มเส้นทาง /api/dispatch/ และแทรกปุ่มจาก HTML response ในหน่วยความจำเท่านั้น ไม่เขียนแก้ไฟล์หน้าแอป บริการย่อภาพ QR ทำในเซิร์ฟเวอร์เอง ไม่ส่งเบอร์พร้อมเพย์ไปเว็บไซต์สร้าง QR ภายนอก

ใช้ Firebase Admin เดิม บันทึกข้อมูลเสริมแยกที่ /kranuanonline/dispatch_v1/state ไม่ทับ /kranuanonline/backend_v1/state เดิม และไม่เปิด Firebase Rules สาธารณะ สลิปเปิดได้เฉพาะลูกค้าและไรเดอร์ของออเดอร์นั้นผ่าน API ที่ตรวจ cookie, CSRF และสิทธิ์ เซิร์ฟเวอร์ไม่ใส่เลขพร้อมเพย์ลงโปรไฟล์ไรเดอร์สาธารณะ

ไฟล์สำหรับพัฒนาต่อ: dispatch-start.cjs (เชื่อมแอปเดิม), dispatch-addon/server.cjs (สิทธิ์/แชท/เงิน/แจ้งเตือน), dispatch-addon/schema.sql (ตารางเสริม), dispatch-addon/promptpay.cjs (payload/CRC/QR), public/dispatch-center/app.js (หน้าจอ), integration.js (ปุ่มในหน้าเดิม)

## ผลทดสอบและข้อจำกัดก่อนเปิดจริง
ผ่านการทดสอบอัตโนมัติ: สิทธิ์คู่สนทนา CSRF/Origin ข้อความซ้ำ เวลาแชทหมดตรง 1 ชั่วโมงและการล้างข้อมูล ยอดค่าบริการจากเซิร์ฟเวอร์ ผู้รับเงินที่อนุมัติเท่านั้น การยืนยันเงินโดยไรเดอร์เท่านั้น เลขอ้างอิงธนาคารไม่ซ้ำ QR/สลิปส่วนตัว ทิปทศนิยม คะแนนปลอม การแจ้งเตือนไม่ซ้ำ และ persistence แยก

ผ่านการเชื่อมกับโค้ด server.cjs ล่าสุดที่อ่านจาก GitHub ในฐานข้อมูลจำลอง: session/CSRF เดิม รับงาน แชท สร้าง QR แจ้งโอน ยืนยันรับเงิน ส่งสำเร็จ และแจ้งคะแนน/ทิปเดิมถึงไรเดอร์ ผ่าน ตรวจการแทรก script ว่าไม่แก้ไฟล์เดิม ไม่ลด security headers และไม่เปลี่ยน JSON error response ผ่าน

ยังไม่ได้ติดตั้งบนเว็บจริงหรือสแกนด้วยแอปธนาคารและบัญชีจริง ก่อนเปิดให้ลูกค้าใช้ ให้เจ้าของบัญชีตรวจชื่อบัญชีและยอด QR กับแอปธนาคารของตนก่อน สถานะการชำระยังอาศัยการตรวจเงินจริงของไรเดอร์ ไม่ใช่ webhook ธนาคาร
