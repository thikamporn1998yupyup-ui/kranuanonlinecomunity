# หน้าจัดการร้านแยก — ไฟล์เสริมเท่านั้น

## ติดตั้ง 3 ขั้นตอน
1. แตก ZIP นี้ จะได้ kranuan-system/public/owner-portal
2. ที่หน้าแรก GitHub repository kranuanonlinecomunity เลือก Add file > Upload files ลากโฟลเดอร์ kranuan-system จาก ZIP นี้ลงไป ตรวจว่ารายการใหม่ทั้งหมดอยู่ใต้ kranuan-system/public/owner-portal/ เท่านั้น แล้ว Commit changes หาก GitHub แจ้งว่ามีไฟล์ใน owner-portal อยู่ก่อนแล้ว ให้หยุดตรวจเทียบ ไม่วางทับทันที
3. รอ Render เป็น Live แล้วเปิด https://kranuanonline888.onrender.com/owner-portal/ และเข้าสู่ระบบด้วยบัญชีร้านค้าเดิม

ชุดนี้มีเฉพาะโฟลเดอร์ใหม่ ไม่มี server.cjs, schema.sql, api.js, admin.js, หน้าแรก, หน้าไรเดอร์, manifest.json หรือ sw.js ของแอปเดิม จึงไม่ย้อนเวอร์ชันที่คุณกำลังอัปเดต และไม่ได้แก้ทางเข้าสู่ระบบเดิม ให้เปิด URL ใหม่โดยตรงหรือบันทึกบุ๊กมาร์กไว้

## เครื่องมือที่พร้อมใช้
- ภาพรวมเฉพาะร้านตนเอง จำนวนออเดอร์รอยืนยัน งานกำลังจัดส่ง และจำนวนเมนู
- เพิ่ม/แก้ภาพหน้าร้าน ชื่อ ที่อยู่ เบอร์โทรและพิกัด
- เพิ่ม/แก้ภาพสินค้า เมนู หรือรายการบริการ พร้อมราคาและการพักรายการ
- เปิด/ปิดรับออเดอร์อาหาร/เครื่องดื่มตามเงื่อนไขตรวจสอบร้านเดิม
- ดูออเดอร์ ยืนยันพร้อมส่ง หรือปฏิเสธออเดอร์ที่รอร้านยืนยัน ส่งต่อเข้าคิวไรเดอร์จริงตามระบบเดิม
- แถบแจ้งเตือนออเดอร์ในหน้าร้าน เสียงเมื่อผู้ใช้เปิด และแจ้งเตือนเบราว์เซอร์เมื่ออนุญาต กดแจ้งเตือนเพื่อเปิดหน้าออเดอร์
- ข้อมูลและแบบฟอร์มหน้าร้านแยกจากแอดมินและไรเดอร์อย่างชัดเจน

บัญชีต้องมี role merchant และผูก shop_id กับร้าน หากยังไม่มี ให้ผู้ดูแลสร้างบัญชีผ่านเครื่องมือเดิม ไม่ต้องสร้าง Firebase ใหม่ การยืนยันร้าน การเปลี่ยนหมวด และโหมดรับออเดอร์ยังเป็นสิทธิ์ผู้ดูแล

## การแจ้งเตือน
เปิดหน้าร้าน > แจ้งเตือน > เปิดเสียง/ทดสอบเสียง และเปิดแจ้งเตือนเบราว์เซอร์ตามต้องการ ต้องเปิดหน้านี้ค้างไว้ ระบบใช้ SSE เดิมและตรวจซ้ำทุก 15 วินาที ไม่แจ้งซ้ำเมื่อออเดอร์เดิมเปลี่ยนสถานะ การเปิดหน้าครั้งแรกแสดงรายการค้างในแถบแต่ไม่ส่งเสียงเตือนย้อนหลังทุกออเดอร์

การแจ้งเตือนเมื่อปิดแอปสนิท การแจ้งเตือนจาก LINE และการทำงานเบื้องหลังบนมือถือยังไม่รวมในชุดนี้ ต้องพัฒนา Web Push/Service Worker ต่อโดยใช้เวอร์ชัน PWA ที่คุณอัปเดตเอง หน้าใหม่นี้ไม่แก้หรือแทนที่ sw.js ของคุณ

## ร้านค้าและผู้ให้บริการ
ร้านอาหาร/เครื่องดื่มรับออเดอร์ได้ตามระบบเดิม หมวดบริการและร้านค้าทั่วไปจัดการแค็ตตาล็อกและราคาได้ แต่ระบบเดิมยังไม่เปิดจองคิวบริการหรือรับชำระเงินสำหรับหมวดเหล่านี้ จึงไม่แสดงปุ่มที่กดแล้วสร้างการจองปลอม สามารถต่อยอดตารางนัดหมาย ใบเสนอราคา หรือประเภทบริการภายหลัง

ยอดสินค้าในงานสำเร็จเป็นมูลค่าจากออเดอร์ล่าสุดที่ API เดิมส่งมา ไม่ใช่ยอดเงินที่ได้รับ ยอดถอน หรือรายได้ทั้งปี

## โครงสร้างสำหรับพัฒนาต่อ
- index.html: หน้าร้านแยก
- merchant.js: Merchant state, merchantLoad, render แต่ละแท็บ, การบันทึกและ merchantDetect สำหรับแจ้งเตือน
- merchant.css: รูปแบบเฉพาะหน้าร้าน
- api-client.js: client แยก ใช้ cookie/CSRF และ API เดิม ไม่แก้ api.js กลาง
- media.js: ย่อภาพและเครื่องมือรูป/dialog เฉพาะหน้านี้
- components.css: สไตล์ส่วนประกอบเฉพาะหน้านี้ ฟอนต์ใช้ assets เดิมและมีฟอนต์สำรอง

API เดิมที่ใช้: /api/session, /api/login, /api/logout, /api/admin/shops, /api/menus, /api/admin/menus, /api/orders, /api/orders/:id/status, /api/events ไม่มี API ใหม่ที่ต้องติดตั้งเซิร์ฟเวอร์เพิ่ม การมีคำ admin ใน URL เดิมไม่ได้ให้สิทธิ์แอดมิน ระบบตรวจ role และ shop_id จากเซิร์ฟเวอร์
